# When to Use MAPS (and When Not To)

**Product MAPS** is the framework. **MAPS** is the four-step loop inside it (Mark, Align, Proceed, Sync).

MAPS is not meant to be used everywhere.
It’s meant to be used at moments of uncertainty—when decisions are expensive to get wrong.

---

## Use MAPS when…

### 1) The problem feels obvious, but outcomes aren’t
If the team agrees on a solution quickly but past attempts haven’t worked, MAPS helps surface hidden assumptions.

Signals:
- “This should be simple…”
- “We’ve tried something like this before”
- “Users just need to understand it better”

### 2) Multiple roles or teams must interpret the same decision
MAPS works well when product, engineering, design, sales, ops, support, or leadership are involved—especially when handoffs are frequent.

A Product Map becomes a shared reference point.

### 3) You’re making a directional bet
Use MAPS before:
- launching a major feature
- entering a new market
- changing onboarding, pricing, or core flows
- replacing an existing system

MAPS makes the bet explicit.

### 4) Feedback is noisy or contradictory
If you’re hearing mixed feedback, conflicting metrics, or strong opinions without shared evidence, MAPS helps separate signal from reaction.

---

## You probably don’t need MAPS when…

### 1) The task is well understood and low risk
Bug fixes, small UI tweaks, routine refactors.

If the outcome is obvious and reversible, a Product Map may be unnecessary.

### 2) You’re mid-flight with no room to change
If a release is locked and no decisions can be influenced, MAPS won’t help much right now.

Use it after launch to learn and adjust.

### 3) You want validation, not clarity
If the decision is already made and MAPS is being used to justify it, it will add friction without insight.

---

## TL;DR — decision checklist
- Is the outcome uncertain or risky? → Use MAPS
- Are multiple teams/roles involved? → Use MAPS
- Are you only validating a finished decision? → Skip MAPS; collect focused feedback instead

---

## Rule of thumb

If answering these questions feels helpful, use MAPS:
- “What are we assuming?”
- “What would make this direction wrong?”
- “What changed since we last decided?”

If not, skip it.
MAPS is a tool—use it deliberately.
